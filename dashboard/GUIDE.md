# 📖 heuristiX 대시보드 사용 설명서

> 브라우저만으로 FJSSP 스케줄링 실험 전체 사이클(벤치마크 선택 → 외란 시나리오 →
> baseline 평가 → LLM 진화 → 인간 vs AI 비교 → 보고서)을 돌리는 방법.

## 띄우기

```bash
cd dashboard
pip install -r requirements.txt
echo "OPENAI_API_KEY=sk-..." > .env     # LLM 기능(진화·자연어 설명)에 필요
python3 seed.py                          # v3 실측 데모 데이터 시드 (최초 1회)
python3 app.py                           # → http://localhost:5000
```

LLM 기능 없이도 시뮬레이션·비교·보고서(자연어 제외)는 모두 작동한다.

## 페이지별 상세

### 1단계 — 준비

#### 🏠 홈 대시보드 (`/`)
전체 현황 요약: 등록된 벤치마크 수, 저장된 실험 결과 수, 최근 진화 기록.
**여기서 할 일은 없고**, 다른 페이지로 가는 허브.

#### 🗄 벤치마크 선택 (`/benchmark-manager`)
실험할 공장 인스턴스(작업×기계 구성)를 고른다.

- **시드된 3개 인스턴스** (12 jobs × 6 machines, 유연도만 다름):
  | 이름 | 의미 |
  |---|---|
  | `synth12x6_flex00` | strict JSSP — 공정당 기계 1대 고정 |
  | `synth12x6_flex05` | moderate FJSSP — 공정당 기계 ~3대 선택 가능 ★추천 |
  | `synth12x6_flex10` | full FJSSP — 아무 기계나 가능 |
- 표준 벤치마크(Brandimarte Mk01~10 등)를 쓰려면:
  `git clone https://github.com/SchedulingLab/fjsp-instances.git fjsp-instances`
- 직접 업로드도 가능 (JSON/TXT, 화면의 형식 안내 참고).

여기서 고른 인스턴스가 다른 모든 페이지의 기본값이 된다 (localStorage 기억).

---

### 2단계 — 실험 설계 & 실행

#### ⚡ 시나리오 설정 & 실행 (`/scenario-manager`)
외란 시나리오를 구성하고 **B1~B10 인간 설계 규칙 10종을 일괄 평가**한다.

- **S0 정상**: 외란 없음. 대조군.
- **S1 부품 지연**: 일부 작업의 부품 도착이 늦어짐.
  | 슬라이더 | 의미 | 권장 시작값 |
  |---|---|---|
  | 영향 비율 (`ratio`) | 전체 작업 중 부품이 늦는 비율 | 0.2 (20%) |
  | 지연 배수 (`k`) | 지연시간 = 평균 처리시간 × k | 1.0 |
  | 발생 타이밍 (`tmin~tmax`) | 시뮬레이션 진행률 기준 발생 구간 | 0.1~0.3 |
- **S2 긴급 주문**: 시뮬레이션 도중 긴급 작업 삽입.
  | 슬라이더 | 의미 | 권장 시작값 |
  |---|---|---|
  | 납기 여유 (`ddf`) | 0.1=매우 촉박 ~ 2.0=여유 | 0.3 (어렵게) |
  | 긴급 건수 (`n_urgent`) | 삽입 작업 수 | 1 |
  | 도착 타이밍 (`amin~amax`) | 도착 구간 | 0.2~0.5 |
- 반복 수(seeds): 클수록 통계가 안정 (30이면 시연에 충분, 논문은 100).

**실행** 클릭 → 진행바 → 완료되면 결과가 자동 저장되고 3단계에서 조회.

#### ⚠️ 이벤트 변환기 (`/event-translator`)
**실세계 공급망 사건을 자연어로 쓰면 LLM이 시나리오 파라미터로 변환**해 준다.

```
입력 예) 유형: 항만 폐쇄 / 지연: 14일 / 영향 부품: 엔진 모듈 / 심각도: 높음
출력 예) S1, ratio=0.4, k=2.5, timing=0.1~0.3  (+근거 설명)
```

출력된 파라미터를 "시나리오 설정"에 그대로 적용할 수 있다.
뉴스 기사 → 시뮬레이션 질문("이 사건이 우리 라인에 어떤 영향?")으로 바로 연결하는 용도.

### 3단계 — 결과 분석

#### 📊 시뮬레이션 결과 (`/simulation-results`)
2단계에서 돌린 baseline 평가 결과를 표·차트로 본다.

- **AT** (평균 납기 초과, 분) — 핵심 지표, 낮을수록 좋음
- **PTJ** (납기 위반 작업 %), **MIT** (기계 유휴시간), **Makespan**
- **ARI** — 최강 baseline 대비 상대 개선 % (양수 = 우위)
- Wilcoxon p-value — 최강 규칙 대비 통계적 차이

읽는 법: AT 오름차순 정렬 → 1위가 그 환경의 최강 인간 규칙.
strict JSSP에선 SPT, FJSSP에선 WMDD/MDD/EDD가 보통 1위 — 환경 따라 강자가 바뀌는 게 핵심 발견.

#### 🔍 규칙 탐색기 (`/rule-explorer`)
**모든 규칙(인간 10 + heuristiX LLM 27 = 37개)의 내부를 들여다보는 곳.**

좌측 목록에서 규칙 클릭하면:
1. **생성 방식** — P1/P2/P3가 무엇인지 설명 (예: "P3: 충격 변수 노출 + 경험 메모리")
2. **heuristiX 학습 환경 카드** — 어떤 시나리오·유연도에서 학습됐고 그때 AT/ARI가 얼마였는지
3. **자연어 설명 보기** 버튼 — LLM이 규칙을 한국어로 풀이
   (한 줄 요약 / 직관 / 강한 상황 / 약한 상황)
4. **이 규칙으로 직접 실험** 카드 — 인스턴스·시나리오·반복 수 골라 시뮬레이터로 재실행
   → AT/PTJ/MIT/ARI 즉시 표시. **학습 환경과 다른 환경에 돌려보면 일반화 능력 테스트**가 된다.
5. **코드** (Monaco 에디터) + 변수 사용 분석 + 계보(부모 규칙)

### 4단계 — AI 규칙 진화

#### 🧬 진화 센터 (`/evolution-center`)
**LLM이 새 dispatching rule을 직접 진화시키는 곳.** (OPENAI_API_KEY 필요)

| 설정 | 의미 | 권장 |
|---|---|---|
| 방식 | P1(충격변수 미노출) / P2(노출) / P3(노출+메모리) | P3 |
| 세대 수 | 진화 반복 횟수 | 5 (시연) ~ 20 (제대로) |
| 시드 수 | 후보 평가당 시뮬레이션 반복 | 10~30 |

**진화 시작** → 실시간 로그 스트리밍 (세대별 best AT 갱신 과정 관찰)
→ 완료되면 결과 파일 저장 → 규칙 탐색기·인간vs AI·보고서에서 활용.

비용 감각: 5세대 × 8규칙 ≈ LLM 호출 40~50회 ≈ $0.02, 3~5분.

#### ⚖️ 인간 vs AI 비교 (`/human-vs-ai`)
**핵심 비교 화면.** B1~B10 (인간 설계) vs LLM 진화 규칙을 같은 환경에서 나란히.

- 막대그래프: 규칙별 AT (인간=회색, AI=색)
- AI 규칙의 ARI가 양수면 → 인간 최강자를 이긴 것
- LLM 자연어 분석 버튼 → "AI가 어떤 차별점으로 이겼는지" 서술형 분석 생성

---

### 5단계 — 심화 분석

#### 🔥 스트레스 테스트 (`/stress-test`)
선택한 규칙(들)을 **여러 외란 강도에 무차별 노출**시켜 robustness를 잰다.
예: S1의 ratio×k 그리드 9개 조합 → 어떤 규칙이 강한 외란에서도 버티는지 히트맵.

#### 🕸 유사도 분석 (`/similarity-analysis`)
규칙들 사이 **코드 유사도 그래프**. LLM이 만든 규칙이 어떤 인간 규칙의 변형인지,
진화 과정에서 어떤 계열이 살아남았는지 시각화.

#### 🧠 경험 메모리 (`/memory-center`) — P3 전용
P3 진화가 누적한 lesson(성공/실패/전략)을 조회.
"slack에 큰 가중치가 효과적" 같은 LLM-S의 교훈이 어떻게 쌓이는지 확인.

### 출력

#### 📄 보고서 생성 (`/report-generator`)
실험 결과를 **MD / PDF / DOCX**로 내보낸다. 포함 섹션 선택 가능:

- 벤치마크 정보 / 시나리오 설정 / 기본 규칙 성능 표
- 진화 결과 + **🗣 규칙 자연어 설명** (LLM이 규칙을 한국어로 풀이)
- **🎯 개선의 구체적 의미** — "+9.7%" 를 *"작업당 평균 5.5분 덜 늦음,
  12건 중 1.8건 더 납기 준수"* 처럼 실무 언어로 자동 환산
- "규칙 자연어 설명 (LLM 호출)" 체크박스로 LLM 사용 on/off

#### ⚙️ 설정 (`/settings`)
전역 기본값: DDT(납기 여유 계수), 기본 반복 수, LLM 모델 등.

## 전체 실험 사이클 예시 (논문 워크플로우)

```
벤치마크 선택(flex05)
  → 시나리오 S1 구성 → baseline 10종 평가 (30 seeds)
  → 진화 센터에서 P1 / P2 / P3 각각 진화 (같은 조건)
  → 인간 vs AI에서 4-way 비교
  → 스트레스 테스트로 best 규칙 robustness 확인
  → 보고서 생성 (DOCX) → 회의 자료
```

## 자주 묻는 것

**Q. 벤치마크 선택이 비어 있어요.**
`python3 seed.py`를 안 돌렸거나, custom 폴더가 빈 경우. seed.py 실행 후 새로고침.

**Q. 자연어 설명/진화가 "API 키 없음" 에러.**
`dashboard/.env`에 `OPENAI_API_KEY=sk-...` 추가 후 서버 재시작.

**Q. heuristiX 규칙을 학습 환경에서 돌렸는데 학습 때 AT와 달라요.**
학습 수치는 Rust 시뮬레이터(heuristiX_v2)에서 측정된 것. 대시보드 내장 Python
시뮬레이터는 구현·인스턴스 시드가 달라 절대값이 다를 수 있다. **같은 대시보드 안에서
규칙끼리 비교**하는 건 공정하다.

**Q. 외부에서 접속하게 하고 싶어요.**
`cloudflared tunnel --no-autoupdate --url http://localhost:5000` → 출력된
trycloudflare.com URL 공유 (프로세스 살아있는 동안만 유효).
